# 本地开发指南

> 启动命令、端口表、日常使用决策树

---

## 一、就绪层级

| 层级   | 含义                          | 由谁保证      | 验证方式        |
| ------ | ----------------------------- | ------------- | --------------- |
| **L0** | Backend + Frontend 进程可响应 | `pnpm start`  | `GET /healthz`  |
| **L1** | Demo 数据 + Platform Key 已 sync | `pnpm reset` | `dev-bootstrap` 脚本自身校验（无独立 readiness 端点） |

---

## 二、命令速查

TokenJoy 支持 **local**（单租户私有化）和 **saas**（多租户平台）两种模式，端口互不冲突，可同时运行。

| 命令               | 用途                                    | 就绪目标 | 使用频率                    |
| ------------------ | --------------------------------------- | -------- | ---------------------------- |
| `pnpm start`       | 启动 apps，默认 local 模式              | L0       | 日常开发                      |
| `pnpm start:local` | 显式启动 apps local 模式                | L0       | 同上                          |
| `pnpm start:saas`  | 启动 apps saas 模式                     | L0       | 测 SaaS 多企业 / 平台管理     |
| `pnpm start:all`   | 并行启动 local + saas                   | L0       | 联调两种模式                   |
| `pnpm reset`       | 重置 apps 库（默认 local，参数 `local`/`saas`） | L1  | 首次 clone / 改 seed / 清库    |
| `pnpm infra`       | 启动两套 Docker 基础设施（saas + local） | 容器 up  | 修 infra 配置                 |
| `pnpm infra:down`  | 停止两套基础设施                        | -        | 清理                           |
| `pnpm lint`        | apps + web + sms 全量 lint              | -        | 提 PR 前                      |
| `pnpm build`       | 构建 apps 前端                          | -        | 发布前                        |

sms 独立命令见 [scripts/dev-sms.sh](../../scripts/dev-sms.sh)：`bash scripts/dev-sms.sh start` / `reset`。

**没有 `pnpm verify`、`pnpm verify gate`、`pnpm verify:integration`、`pnpm lint:sms`、`pnpm start:newapi`、`pnpm start:infra` 这些命令**——`package.json` 未定义，执行会直接报错（`Missing script`）。CI（`.github/workflows/ci.yml`）里引用 `pnpm verify` 目前会失败，属已知待修工程问题（见 [problems.md](./problems.md)）。

## 三、reset 详解

```bash
pnpm reset [local|saas]
```

| 参数    | 默认 | 说明                                     |
| ------- | ---- | ---------------------------------------- |
| `local` | ✅   | 单租户私有化模式：空库，下次启动走 setup 流程 |
| `saas`  |      | 多租户平台 + demo 公司（完整 seed）        |

**reset 阶段链**：

1. `docker compose up postgres redis --wait` — 基础设施就绪（按模式使用对应 compose 文件）
2. SQL `DROP/CREATE DATABASE` — 重建 `tokenjoy` + `newapi` + `logs` 三个库
3. `bootstrap-local-after-reset.sh` — 初始化 NewAPI
4. Redis `FLUSHDB`（db 0 和 2）
5. `pnpm -F @tokenjoy/backend dev-bootstrap`（`go run ./cmd/dev-bootstrap`）— seed 数据 + Platform Key sync
6. `setup-dev-mock-channel.sh` — 配置测试模型通道

sms reset 走独立脚本 `scripts/dev-sms.sh reset`：重建 `sms`/`sms_newapi` 库 + `pnpm -F @sms/backend seed`。

## 五、测试命令

| 命令                        | 说明                                |
| --------------------------- | ----------------------------------- |
| `pnpm test`                 | apps 全量测试（frontend + backend，按 `TEST_MODE` 循环） |
| `pnpm test:sms`             | sms 全量测试（frontend + backend）  |
| `pnpm test:integration`     | apps 后端集成测试                   |
| `pnpm test:sms:integration` | sms 后端集成测试                    |
| `pnpm test:e2e`             | apps 前端 E2E                       |
| `pnpm test:sms:e2e`         | sms 前端 E2E                        |
| `pnpm lint`                 | apps + web + sms 全量 lint（单条命令，无独立 `lint:sms`） |

后端单测（`apps/backend/` 下）：`make test-unit`（需 PostgreSQL）、`make test-fast`（仅 `tests/pkg/...`，无需数据库）。
