# 本地开发指南

> 启动命令、就绪层级、日常使用决策树

---

## 一、就绪层级

| 层级 | 含义 | 由谁保证 | 验证方式 |
|------|------|----------|----------|
| **L0** | Backend + Frontend 进程可响应 | `pnpm start` | `GET /healthz` |
| **L1** | Demo 数据 + Platform Key 已 sync | `pnpm reset` | `GET /api/dev/readiness` |
| **L2** | Gateway + 模拟消耗全通路 | `pnpm verify gate` | gate 脚本自验 |

---

## 二、命令速查

| 命令 | 用途 | 就绪目标 | 使用频率 |
|------|------|----------|----------|
| `pnpm reset` | 清 apps 库重建、种子数据 | L1 | 首次 clone / 改 seed / 清库 |
| `pnpm reset saas` | 多租户模式重建 | L1 | 测 SaaS 多企业 |
| `pnpm reset sms` | 清 sms 库重建、种子数据 | - | sms 开发 |
| `pnpm reset all` | 同时重建 apps + sms | L1 | 全量清库 |
| `pnpm start` | 启动 apps（backend + frontend + mock） | L0 | 测 Gateway / 模拟消耗 |
| `pnpm start sms` | 启动 sms（backend + frontend） | L0 | sms 开发 |
| `pnpm start all` | 并行启动 apps + sms | L0 | 联调 |
| `pnpm infra` | 启动 Docker 基础设施 | 容器 up | 修 infra 配置 |
| `pnpm verify` | CI 检查（lint + test + build） | - | 提 PR 前 |
| `pnpm verify gate` | 全链路网关冒烟 | L2 | 通路验收 |

## 三、reset 详解

```bash
pnpm reset [local|saas] [--empty|--minimal|--full]
pnpm reset sms
pnpm reset all
```

| 参数 | 默认 | 说明 |
|------|------|------|
| `local` | ✅ | 单公司模式 |
| `saas` | | 多租户平台 + demo 公司（强制 full seed） |
| `sms` | | 仅重置 sms 相关 database |
| `all` | | apps + sms 全部重置 |
| `--empty` | | 空库，仅 admin 可登录 |
| `--minimal` | | 最小 seed |
| `--full` | ✅ | 完整 demo 数据 |

**reset 阶段链（apps）**：

1. `docker compose up postgres redis --wait` — 基础设施就绪
2. SQL `DROP/CREATE DATABASE` — 只动 tokenjoy、newapi、logs 三个库
3. `bootstrap-local-after-reset.sh` — 初始化 NewAPI
4. `redis FLUSHDB` — 清 apps 相关的 Redis db（0 和 2）
5. `dev-bootstrap`（Go）— seed 数据 + Platform Key sync
6. `setup-dev-mock-channel.sh` — 配置测试模型通道

**reset 阶段链（sms）**：

1. `docker compose up postgres --wait` — 基础设施就绪
2. SQL `DROP/CREATE DATABASE` — 只动 sms、sms_newapi、sms_logs 三个库
3. `pnpm -F @sms/backend seed` — schema + 种子数据
