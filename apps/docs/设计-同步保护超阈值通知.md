# PRD：组织同步删除保护与超阈值通知

> **优先级**：P1  
> **角色**：超级管理员 / 组织管理员  
> **前置**：US-01 凭证已配置、US-03 定时同步已启用  
> **日期**：2026-07-27

---

## 1. 问题场景

企业将飞书/钉钉/企微作为组织架构的唯一数据源，通过定时同步保持 TokenJoy 侧数据与第三方一致。**删除保护**是最核心的安全机制——当第三方数据异常（如误操作批量离职、API 返回不完整、凭证权限缩小等）导致 Diff 中出现大规模删除时，系统必须自动终止同步并即时通知管理者介入。

**不通知 = 发现问题依赖人工巡检同步日志 = 可能延迟数小时甚至到下一个工作日。**

这个时间窗口内，如果管理员不知道同步已中断，新入职成员无法被自动导入，组织数据开始偏离。

---

## 2. 用户故事

> 作为**超级管理员**，当定时同步因删除数量超过保护阈值而被自动终止时，我希望**立即收到通知**（通过我配置的渠道），以便我能及时排查原因并决定是否手动执行同步或调整阈值。

---

## 3. 功能规格

### 3.1 触发条件

| 条件 | 说明 |
|------|------|
| 成员删除超阈值 | `待删除成员数 > deleteMemberThreshold` |
| 部门删除超阈值 | `待删除部门数 > deleteDepartmentThreshold` |
| 触发时机 | Diff 计算完毕、Apply 执行前 |
| 触发来源 | 定时同步 **或** 手动触发同步 |

两个阈值独立判断，任一超过即终止。

### 3.2 终止行为

1. **不执行任何变更**——Diff 中的新增、修改、删除均不 Apply
2. **写入 SyncLog**——类型=当次同步类型（定时/手动），结果=失败，详情=具体超阈值信息
3. **触发通知**——按 §3.3 投递

### 3.3 通知规格

#### 通知接收人

**本企业所有超级管理员 + 组织管理员**（`RoleSuperAdmin` / `RoleOrgAdmin`，状态=启用）。

设计理由：
- 同步保护是企业级安全事件，不应只通知单人
- 超管和组织管理员都有组织架构管理权限，需要知晓
- 无需成员自行订阅——这是系统强制通知

#### 通知渠道

由管理员在「数据源 → 定时同步配置」中选择（多选）：

| 配置项 | 投递渠道 | 当前状态 |
|--------|---------|---------|
| 手机短信 (`notifyPhone`) | SMS（阿里云） | ✅ 基础设施就绪 |
| 邮箱 (`notifyEmail`) | Email（Resend） | ✅ 基础设施就绪 |
| IM 通知 (`notifyIm`) | IM Bot（飞书/钉钉/企微） | ❌ 未实现，降级为站内通知 |

**附加规则**：
- **站内通知始终投递**，无论管理员是否勾选其他渠道——确保超管登录后必然可见
- 渠道未配置（如 SMS 缺凭证）时**静默跳过**该渠道，不阻塞其他渠道投递
- 投递失败不影响同步终止逻辑（通知是 best-effort）

#### 通知内容

**站内通知 / IM**：

```
标题：组织同步保护触发
正文：组织同步检测到需删除 {deleteCount} 名成员（/{deleteDeptCount} 个部门），
      超过保护阈值（成员 {memberThreshold} / 部门 {deptThreshold}），同步已自动终止。
      请检查第三方平台数据是否正常，确认后可手动重新触发同步或调整阈值。
操作：[查看数据源配置]  →  /org/data-source
```

**短信**（≤70 字）：

```
【TokenJoy】组织同步保护触发：需删除{n}人超阈值{t}，同步已终止。请登录处理。
```

**邮件**：

```
主题：[TokenJoy] 组织同步保护触发 - 需要您介入

正文：
  {管理员姓名}，您好：

  {企业名称} 的组织定时同步在 {时间} 因触发删除保护而自动终止。

  详情：
  · 待删除成员：{memberDeleteCount} 人（阈值：{memberThreshold}）
  · 待删除部门：{deptDeleteCount} 个（阈值：{deptThreshold}）
  · 同步类型：{定时/手动}

  可能原因：
  · 第三方平台发生批量离职操作
  · 数据源凭证权限范围缩小
  · 第三方 API 返回数据不完整

  建议操作：
  1. 登录第三方平台确认组织数据是否正常
  2. 如确认删除合理，可在 TokenJoy 调高阈值后重新触发同步
  3. 如数据异常，请先修复第三方数据后再同步

  [登录 TokenJoy 查看 →]

  ---
  此邮件由 TokenJoy 系统自动发送，请勿回复。
```

## 4. 业务规则

| # | 规则 | 说明 |
|---|------|------|
| R1 | 阈值 = 0 表示不启用该维度的保护 | 设为 0 时即使删除 100 人也不终止 |
| R2 | 两个阈值独立判断 | 成员超但部门不超 → 仍然终止 |
| R3 | 手动触发同步同样受阈值保护 | 不区分定时/手动 |
| R4 | 终止后不自动恢复 | 下次定时仍会尝试，如果数据未变则仍触发 |
| R5 | 通知不影响终止 | 即使所有渠道都发送失败，同步仍是终止状态 |
| R6 | 无需用户确认即终止 | 安全优先，默认阻断 |

---

## 5. 验收标准

| # | GIVEN | WHEN | THEN |
|---|-------|------|------|
| 1 | 阈值 10 人 / 5 部门，notifyEmail=true，企业有 2 名超管 | 定时同步 Diff 含 15 人待删除 | 同步终止 + SyncLog 记录失败 + 2 名超管各收到 1 封邮件 + 2 条站内通知 |
| 2 | 阈值 10 人 / 5 部门 | Diff 含 3 人待删除、2 部门待删除 | 正常执行同步，不触发通知 |
| 3 | 阈值 10 人，notifyPhone=true，SMS 渠道未配置 | Diff 含 20 人待删除 | 同步终止 + 站内通知到达 + SMS 静默跳过 |
| 4 | 阈值成员=0（禁用），部门=5 | Diff 含 50 人、8 部门待删除 | 成员维度不检查 + 部门超阈值 → 终止 |
| 5 | notifyIm=true，IM Bot 未实现 | 超阈值触发 | 降级为站内通知投递 |
| 6 | 超管手动点击「立即同步」 | Diff 超阈值 | 同样终止 + 通知（与定时触发行为一致） |
| 7 | 企业无超管/组织管理员（极端情况） | 超阈值触发 | 同步终止 + SyncLog 记录 + 无通知投递（无可用接收人） |
| 8 | 连续 3 次定时同步都超阈值 | 每次触发 | 每次都发通知（不做去重——每次超阈值都是需要关注的事件） |

---

## 6. 异常处理

| 场景 | 处理 |
|------|------|
| 第三方 API 超时/不可达 | 同步失败（凭证级别错误），不涉及阈值检查 |
| Diff 计算出错 | 同步失败，写 SyncLog，不触发阈值通知 |
| 通知服务不可用 | best-effort，日志记录失败原因 |
| 阈值配置为负数 | 前端校验 min=0；后端兜底：负数视为 0（禁用） |
| 同步正在执行中再次触发 | 获取锁失败 → 跳过本次（已实现） |

## 7. 数据模型

### SyncConfig（已有，无需变更）

| 字段 | 类型 | 说明 |
|------|------|------|
| enabled | bool | 定时同步开关 |
| startTime | string | 每日开始时间（HH:mm） |
| frequencyHours | int | 频率（6/12/24） |
| deleteMemberThreshold | int | 成员删除保护阈值 |
| deleteDepartmentThreshold | int | 部门删除保护阈值 |
| notifyPhone | bool | 超阈值时通过 SMS 通知 |
| notifyEmail | bool | 超阈值时通过 Email 通知 |
| notifyIm | bool | 超阈值时通过 IM 通知（当前降级） |

### SyncLog（已有，无需变更）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | |
| time | string | 同步时间 |
| type | string | manual / scheduled |
| result | string | success / partial_failure / failure |
| detail | string | 人类可读描述 |

## 8. 非功能需求

| 维度 | 要求 |
|------|------|
| 延迟 | 通知应在同步终止后 30 秒内到达站内；Email/SMS 受外部服务延迟影响，5 分钟内 |
| 可靠性 | 站内通知必达（同步写入 PG）；外部渠道 best-effort |
| 安全 | 通知内容不含成员姓名等 PII，仅展示数量 |
| 可观测 | 通知投递结果记录在 notification_logs，可通过审计查看 |

---

## 9. 不做

| 事项 | 理由 |
|------|------|
| 超阈值后自动恢复/重试 | 需要人工判断是否真实变更，自动恢复有数据丢失风险 |
| 细粒度配置每人的通知渠道 | 这是系统级安全事件，强制通知所有管理员，不需要个人偏好 |
| 去重（同一天只通知一次） | 每次超阈值都是独立事件，管理员需要知道同步持续失败 |
| 通知中展示具体待删除的人名列表 | 数据量不确定 + PII 风险；管理员应登录平台查看同步日志详情 |
| IM Bot 渠道实现 | 独立特性，本 PRD 仅定义降级策略 |

---

## 10. IM Bot 升级路径

当 IM Bot Channel 实现后：

1. `notifyIm=true` 从降级 InApp 改为投递 IM Bot
2. IM Bot 消息内容复用站内通知的 title + body
3. 无需修改 SyncConfig 数据模型、前端 UI、触发逻辑
