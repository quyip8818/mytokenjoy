# 预算分配与扣减

本文是**开发指导文档**，描述现有预算系统的架构、数据流和扩展约定。面向需要修改或扩展预算功能的开发者。

---

## 1. 核心概念

系统将预算管理分为**配置层**和**运行时层**两个独立关注点：

- **配置层**：回答「蛋糕怎么切」——部门总额如何分配给子部门、预留池、项目、成员个人额度。
- **运行时层**：回答「这次 API 调用能不能放行、钱从哪扣」——按 Key scope 走不同的预检/入账路径。

两层之间通过 `budget_consumed` 表的三个轴（axis）松耦合。配置只约束分配合法性；运行时只看对应轴的实际消耗 vs 上限。

---

## 2. 三种 Key Scope

定义在 `domain/types/keys.go`：

| Scope    | 常量             | 计费来源                                 | 必须字段                 |
| -------- | ---------------- | ---------------------------------------- | ------------------------ |
| 个人     | `member`         | 成员 personal budget                     | `memberID`               |
| 项目     | `project`        | 项目 budget                              | `projectID`              |
| 项目成员 | `project_member` | 项目内子额度 (`MemberBudgets[memberID]`) | `memberID` + `projectID` |

**关键原则：scope 之间不兜底。** 个人额度用尽不能花项目池；项目额度用尽不能花个人池。

---

## 3. 运行时预检：GatewayChainRemain

核心函数位于 `pkg/budget/chain.go`。

```go
func GatewayChainRemain(scope string, in ChainInputs) (remain float64, limiting string, uncapped bool)
```

按 scope 取各候选池剩余的**最小值**作为可用额度：

| Scope            | 候选池                         |
| ---------------- | ------------------------------ |
| `member`         | Key 剩余, personal 剩余        |
| `project`        | Key 剩余, 项目剩余             |
| `project_member` | Key 剩余, 子额度剩余, 项目剩余 |

各剩余计算公式：

- Key 剩余 = `KeyBudget - KeyConsumed`（KeyBudget=0 表示不设 Key 上限，跳过）
- Personal 剩余 = `PersonalCap - PersonalConsumed`
- 项目剩余 = `ProjectCap - ProjectConsumed`
- 子额度剩余 = `MemberBudget - SubConsumed`

**不参与预检的：** 未分配配置余量、部门报表总额、预留池。

企业钱包 (`wallet_remain_quota`) 在网关层独立检查，不进入 `GatewayChainRemain`。

### 3.1 ChainInputs 构建

`pkg/budget/mapping_remain.go` → `BuildChainInputs` / `BuildChainInputsPreloaded`

数据来源：

- `budget_consumed` 表按 `(axis_kind, axis_id, period_key)` 查询实际消耗
- `PlatformKey.Budget` → Key 上限
- `Member.PersonalBudget` → 个人上限
- `Project.Budget` → 项目上限
- `Project.MemberBudgets[memberID]` → 子额度上限

### 3.2 combined_key_remain 缓存

`domain/budget/combined_key_summary.go` 预计算所有活跃 Key 的链式剩余，写入 `combined_key_summaries` 表。网关用此值做快速预检，不必每次实时计算。

触发刷新的时机：

- 消耗入账后（异步 job）
- Key 创建/更新后
- 预算配置变更后（通过 `JobEnqueuer` 调度）

可选 Redis 层（`CombinedKeyCache`）进一步加速热路径，PG 始终是权威来源。

## 4. 消耗入账：consumed_attrib

`domain/budget/consumed_attrib.go` → `ConsumptionDeltas`

一次 API 调用结算后，按 scope 计算轴增量：

| Scope            | 写入轴                     |
| ---------------- | -------------------------- |
| `member`         | `platform_key` + `member`  |
| `project`        | `platform_key` + `project` |
| `project_member` | `platform_key` + `project` |

注意 `project_member` 的子额度消耗**不单独写轴**——通过聚合该成员在该项目下所有 `project_member` Key 的 `platform_key` 轴消耗得出 (`SumProjectMemberKeyConsumed`)。

---

## 5. 超支封禁：OverrunService

`domain/budget/overrun.go`

消耗入账后异步触发，按优先级依次检查：

1. **Key 级**：`consumed >= budget` → 禁用该 Key
2. **Member 级**（仅 member scope）：personal consumed >= cap → 禁用该成员所有 member Key
3. **ProjectMember 级**：子额度用尽 → 禁用该成员在该项目的 project_member Key
4. **Project 级**：项目 consumed >= budget → 禁用该项目所有 project/project_member Key
5. **Department 级**：ledger 聚合 >= 部门 budget → **仅通知，不禁用 Key**

找到第一个触发的层级就执行动作并返回（短路）。

---

## 6. 企业钱包与 Lot 消耗

`domain/billing/lot/consume.go`

钱包是全公司硬顶，与组织预算独立。采用 FIFO Lot 消耗模型：

1. `Company.LockForUpdate` 获取行锁
2. 按 `fifo_head_lot_id` 遍历 active lot，依次扣减 `quota_remaining`
3. 所有 lot 耗尽仍不够 → 扩展 overdraft lot（透支）
4. 更新 `wallet_remain_quota`

充值写入（`CreditFromLot`）遵循「先同步外部网关，再提交本地事务」策略，保证用户不会出现「本地有余额但网关拒绝」的情况。

## 7. 配置层：预算树

### 7.1 组织树 (BudgetNode)

`pkg/budget/tree.go` + `domain/budget/tree_mutate.go`

部门预算以树形结构存储，每个节点包含：

- `Budget`：部门总额
- `ReservedPool`：预留池（审批追加用，不参与运行时预检）
- `Children`：子部门

守恒约束：

```
部门总额 >= 子部门之和 + 预留池 + 项目之和 + 成员 personal 之和
```

剩余部分为「未分配」（配置余量），仅供 TL 继续分配，不参与运行时消耗。

### 7.2 成员 Personal Budget

`pkg/budget/memberbudget.go`

- `GetPersonalBudget`：取成员个人额度（未设置则用 `DefaultPersonalBudget`）
- `ValidateMemberBudgetUpdate`：校验新额度不超出部门可分配容量 (`GetMemberBudgetCapacity`)
- Key 创建时：`ValidateMemberScopeKeyBudget` 校验 Key 额度不超出 personal 剩余可分配

### 7.3 项目 Budget

`pkg/budget/projectbudget.go` + `pkg/budget/scope_validate.go`

- `ValidateProjectKeyBudget`：校验 project scope Key 额度不超出项目可分配
- `ValidateProjectMemberKeyBudget`：校验 project_member Key 额度不超出子额度可分配
- `ValidateProjectMemberRoster`：确认成员在项目 roster 且已设置 `member_budget > 0`

## 8. 账期 (Period)

`pkg/budget/period.go`

预算以账期为周期重置消耗。每个部门可配置 period（目前支持 monthly）。

两种 period 类型（类型安全，不可混用）：

- `OpenBudgetPeriod`：从业务时钟派生，用于预检和入账写入
- `OccurrencePeriod`：从事件发生时间派生，仅用于 ledger 归档

`OpenDepartmentPeriod(ctx, nodes, deptID, clock)` 是获取当前开放账期的标准入口。

## 9. 数据存储

| 表                                            | 用途                                                                     |
| --------------------------------------------- | ------------------------------------------------------------------------ |
| `budget_consumed`                             | 三轴消耗事实表 `(company_id, axis_kind, axis_id, period_key) → consumed` |
| `combined_key_summaries`                      | 预计算链式剩余，网关快速预检                                             |
| `recharge_lots`                               | 钱包 FIFO lot 队列                                                       |
| `companies.wallet_remain_quota`               | 钱包余额快照                                                             |
| `org_nodes`                                   | 组织树 + 部门预算配置                                                    |
| `members.personal_budget`                     | 个人额度                                                                 |
| `projects.budget` / `projects.member_budgets` | 项目额度 + 子额度                                                        |
| `platform_keys.budget` / `.consumed`          | Key 级别上限与已消耗                                                     |

## 10. 包职责分工

| 包                   | 职责                                                           | 是否有副作用     |
| -------------------- | -------------------------------------------------------------- | ---------------- |
| `pkg/budget`         | 纯计算：chain remain、tree 操作、校验、period 解析             | 无（纯函数）     |
| `domain/budget`      | 编排：service CRUD、overrun 处理、reconcile、combined key 刷新 | 有（读写 store） |

| `domain/billing/lot` | lot 消耗引擎（FIFO + overdraft）                               | 有               |

## 11. 扩展指南

### 新增预检层级

1. 在 `ChainInputs` 添加字段
2. 在 `GatewayChainRemain` 的对应 scope case 添加 candidate
3. 在 `BuildChainInputs` / `BuildChainInputsPreloaded` 填充新字段
4. 在 `OverrunService.evaluateOverrun` 添加对应封禁逻辑
5. 刷新 `combined_key_summaries`

### 新增 Key Scope

1. 在 `domain/types/keys.go` 添加常量
2. `ValidPlatformKeyScope` 添加 case
3. `GatewayChainRemain` 添加 scope case
4. `ConsumptionDeltas` 添加入账轴
5. `OverrunService` 添加对应检查
6. `ValidatePlatformKeyScope` 添加字段校验

### 调整配置守恒规则

修改 `pkg/budget/memberbudget.go` → `GetMemberBudgetCapacity` 和 `ValidateMemberBudgetUpdate`。项目侧类似修改 `ValidateProjectKeyBudget`。

## 12. 关键不变量

1. **scope 间不兜底**：member Key 永远只扣 personal；project Key 永远只扣项目池。
2. **部门 ledger 仅通知**：部门维度消耗达到预算只发预警，不封 Key。
3. **未分配不参与运行时**：配置余量仅供 TL 继续分配，预检链不考虑。
4. **Personal 用尽即阻断**：member scope Key 被禁用；恢复路径是预留池审批追加到 `personal_budget`。
5. **combined_key_remain 是缓存**：PG `budget_consumed` 是唯一权威来源；summary 可重算。
6. **Lot 消耗不可逆**：overdraft lot 扩展后只能通过充值覆盖，不会自动回退。
7. **子额度是 Key 聚合**：`project_member` 不单独写 member 轴，通过聚合 Key 轴得出实际消耗。
