# 月度预算管理 — 架构分析

## 现状

| 数据 | 存储位置 | 按月隔离？ |
|------|----------|:---:|
| 部门预算 / 预留池 | `org_nodes.budget`, `org_nodes.reserved_pool` | ❌ 全局唯一值 |
| 成员额度 | `members.personal_budget` | ❌ |
| 项目预算 | `projects.budget` | ❌ |
| 消耗 | `budget_consumed` (axis_kind, axis_id, **period_key**) | ✅ |

配置值全局一份，消耗按月隔离。要实现"回顾历史月 + 预配下月"需要额外存储。

---

## 方案：单表 `budget_snapshot`

### 设计思路

读模式是"给我某月完整的预算树"——那就直接按月存一棵完整的树。

```
┌──────────────────────────────────────────────────────┐
│ org_nodes / members / projects                        │ ← 当前生效值（不改）
│ (Gateway / Ingest / Rebalance 读这里)                │
└──────────────────────────────────────────────────────┘
                         │
                    月初拍快照 ↓ / 预配写入
                         │
┌──────────────────────────────────────────────────────┐
│ budget_snapshot (company_id, period_key) → JSONB     │ ← 历史 + 下月预配
└──────────────────────────────────────────────────────┘
                         │
                    变更时 append ↓
                         │
┌──────────────────────────────────────────────────────┐
│ operation_logs（已有）                                │ ← 变更审计
└──────────────────────────────────────────────────────┘
```

### DDL

```sql
CREATE TABLE IF NOT EXISTS budget_snapshot (
    company_id  UUID NOT NULL REFERENCES companies (id) ON DELETE CASCADE,
    period_key  TEXT NOT NULL,          -- "2026-08", "2026-09"
    snapshot    JSONB NOT NULL,         -- 完整预算树 + 成员额度 + 项目
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (company_id, period_key)
);
```

一张表。一个 PK 查询。零 ALTER 现有表。

### snapshot JSONB 结构

与 `GET /budget/tree` 返回值同构，外加 members 和 projects：

```jsonc
{
  "tree": [
    {
      "id": "...", "name": "九霄云聚", "budget": 100, "reservedPool": 10,
      "memberAvgBudget": 5000, "children": [...]
    }
  ],
  "members": [
    { "memberId": "...", "departmentId": "...", "personalBudget": 5000 }
  ],
  "projects": [
    { "id": "...", "name": "...", "budget": 3000, "ownerDepartmentId": "...", "memberBudgets": {} }
  ]
}
```

前端收到直接渲染——格式跟现有 API 返回一致，不需要新的解析逻辑。

## 读写路径

### 读

| 请求 | 逻辑 |
|------|------|
| `GET /budget/tree`（当前月或无 period） | **不变**：读 org_nodes 构建树 + `usage_ledger` 按 department_id 聚合填 consumed（read-time enrichment） |
| `GET /budget/tree?period=2026-07`（历史月） | 读 `budget_snapshot` WHERE period_key='2026-07'，返回 snapshot.tree（含 consumed，rotation 存档时已固化） |
| `GET /budget/tree?period=2026-09`（下月预配） | 读 `budget_snapshot` WHERE period_key='2026-09'。无记录 → fallback 返回 live tree（consumed=0，下月还没消费） |

### 写

| 操作 | 当前月 | 下月预配 |
|------|--------|----------|
| 改部门预算 | 现有逻辑不变（写 org_nodes） | 读当前 snapshot → 修改对应节点 → UPSERT budget_snapshot |
| 改成员额度 | 现有逻辑不变（写 members） | 同上，修改 snapshot.members |
| 改项目预算 | 现有逻辑不变（写 projects） | 同上，修改 snapshot.projects |
| Copy（继承本月） | — | 读当前 org_nodes/members/projects 拼 JSON → INSERT budget_snapshot |

**当月写入的所有代码完全不动。**

## 月初 Rotation

```
每月1日（或 lazy 首次请求时）：

1. 拍摄上月快照（如果还没拍）
   → 读当前 org_nodes/members/projects → INSERT budget_snapshot(上月 period_key)

2. 应用下月预配（如果有）
   → 读 budget_snapshot(当月 period_key)
   → 事务写入 org_nodes.budget / members.personal_budget / projects.budget
   → 只 apply snapshot 中仍存在于系统中的实体（跳过已删除的成员/部门/项目）
   → 新增实体（拍快照后新加入的成员/部门）沿用默认值，不受 snapshot 影响
   → 触发 company rebalance

3. 无预配时什么都不做（沿用上月值，consumed 自动归零新 period）
```

### 触发方式

推荐 **lazy rotation**：`GET /budget/tree` handler 里检查 `tenant_background_state.last_rebalanced_period < current_period`，首次命中时同步执行。已有 `last_rebalanced_period` 字段可复用。

### 实体增删边界

| 场景 | Rotation 行为 |
|------|--------------|
| snapshot 中有 member A，但 A 已从系统中删除 | 跳过，不报错 |
| 系统中有 member B，但 snapshot 中无 B | B 保持当前 personal_budget 不变 |
| snapshot 中有 project X，但 X 已被删除 | 跳过 |
| 月中新增部门 C，snapshot 中无 C | C 保持当前 budget=0 不变 |

## 变更审计

### 前置工作：补齐预算变更日志（已完成）

budget domain 已在 UpdateNode / UpdateMemberBudget / 项目 CRUD 中补上 `AppendOperationLog` 调用（参照 billing domain 的写法，通过 audit.go helper）。

### 月度预算变更

复用已有的 `operation_logs` 表：

```go
// 每次预算修改时同事务写入
operationLog := OperationLog{
    Action:   "budget.update",
    Target:   nodeID.String(),
    Detail:   `{"period":"2026-09","field":"budget","old":100,"new":60}`,
    Operator: operatorID,
}
```

不新建审计表。operation_logs.detail 存 JSON 字符串，包含 old/new value、period、字段名。前端审计页面已有渲染 operation_logs 的能力。

## 新增 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/budget/tree?period=YYYY-MM` | 扩展现有 handler，有 period 时读 snapshot |
| POST | `/budget/periods/copy` | body: `{to: "2026-09"}`。拍当前状态为下月快照 |
| PUT | `/budget/snapshot/{period}/departments/{id}` | 修改下月预配中某部门预算 |
| PUT | `/budget/snapshot/{period}/members/{id}` | 修改下月预配中某成员额度 |
| PUT | `/budget/snapshot/{period}/projects/{id}` | 修改下月预配中某项目预算 |

或更简单：所有现有 PUT 加 `?period=YYYY-MM` 参数，handler 内 if/else 分发。

### 下月预配编辑限制

| 可做 | 不可做 |
|------|--------|
| 修改已有部门的 budget / reservedPool | ~~新建/删除部门~~ |
| 修改已有成员的 personalBudget | ~~新建/删除成员~~ |
| 修改已有项目的 budget | ~~新建/删除项目~~（项目 FK 依赖主表） |

新建/删除实体只能在当月操作（写入主表后自然带入下月 snapshot）。

## 并发控制

snapshot 的写操作是**读-改-写**（整个 JSONB）：读取当前 snapshot → 修改对应节点 → 写回。

```go
// 写 snapshot 时加行锁防止并发丢失
func updateSnapshot(ctx context.Context, tx store.Store, periodKey string, mutate func(*Snapshot)) error {
    // SELECT ... FOR UPDATE
    snapshot, err := tx.BudgetSnapshot().GetForUpdate(ctx, periodKey)
    if err != nil { return err }
    mutate(&snapshot)
    return tx.BudgetSnapshot().Upsert(ctx, periodKey, snapshot)
}
```

使用现有的 `store.WithTx` + `SELECT FOR UPDATE` 即可。不需要额外的乐观锁版本号——预算配置的并发写频率极低（管理员手动操作）。

## 为什么这是最佳方案

| 维度 | 说明 |
|------|------|
| 简单 | 一张新表，零 ALTER，零 merge 逻辑 |
| 读快 | 一次 PK 查询返回完整月度快照 |
| 写不冲突 | 当月写 org_nodes（不变），下月写 snapshot（独立） |
| 审计 | 复用 operation_logs，不新建 |
| 冗余可控 | 一条 snapshot ≈ 几十 KB，一年 12 条，十年 120 条 |
| 前端零适配 | snapshot 格式 = 现有 API 返回结构 |
| 运行时零影响 | Gateway/Ingest/Rebalance 完全不感知 |

### Rotation 触发路径

| 路径 | 触发方 | 时机 |
|------|--------|------|
| Lazy | `GetTree()` → `MaybeRotatePeriod()` | 新月首次用户访问 |
| Eager | `RebalanceWorker` → `RotatePeriod()` | watchdog 检测到月份翻转 |

两条路径共享 `doRotate`，通过 `LastRebalancedPeriod` 幂等。

### 前端编辑规则

| 月份 | 可编辑 | 可创建/删除实体 | 数据来源 |
|------|--------|----------------|----------|
| 过去月 | ❌ | ❌ | snapshot |
| 本月 | ✅ | ✅ | live + ledger enrichment |
| 下月（无 snapshot） | ✅ | ❌ | fallback live（首次编辑触发 copy-on-write） |
| 下月（有 snapshot） | ✅ | ❌ | snapshot |
