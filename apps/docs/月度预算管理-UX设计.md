# 月度预算管理 — UX 设计

## 设计原则

1. **延续而非重造**：保持现有左树右详情布局，新增的月度控件是"叠加层"而非"替代层"。
2. **状态一目了然**：任何时候用户都能瞬间分辨"我在看哪个月"、"可以改还是只能看"。
3. **危险操作有缓冲**：当月不可下调，下调只作用于未来，给团队过渡期。
4. **引导优于报错**：下调时不只是说"不行"，而是告诉用户"怎样才行"。

## Period Bar 组件

### 视觉规格

```
高度: 44px
背景: bg-card (与 SplitPanel 融为一体)
底边框: border-b border-border
内边距: px-5
布局: flex items-center justify-between
```

### 左区 — 月份导航

```
┌───────────────────────────────────────────────────┐
│  [◀]   2026年8月   [Badge]   [▶]                  │
└───────────────────────────────────────────────────┘

◀ ▶ = IconButton (ghost, size-7)
月份文字 = text-sm font-semibold text-foreground，可点击弹出月份 Picker
Badge = StatusBadge 组件
```

### 月份 Badge 三态

| 状态 | Badge variant | 文字 | 含义 |
|------|--------------|------|------|
| 过去 | `neutral` (bg-slate-100 text-slate-600) | 已结束 | 只读，不可编辑 |
| 当月 | `info` (bg-blue-50 text-blue-700) | 本月 | 可编辑（仅上调） |
| 下月 | `warning` (bg-amber-50 text-amber-700) | 预配中 | 可自由编辑（含下调） |

### 右区 — 快捷操作

| 条件 | 显示 |
|------|------|
| 当前月视图 | `[预配下月 →]` Button(ghost) |
| 下月视图 & 无预配记录 | `[继承本月配置]` Button(outline) |
| 下月视图 & 已有记录 | 无按钮 |
| 过去月视图 | 无按钮 |

### 箭头边界

- 左箭头：最早到公司首条预算月份，到达最早月时 `disabled`。
- 右箭头：最晚到当前月 +1（下月），到达时 `disabled`。

### 月份 Picker (可选交互)

点击月份文字弹出 `Popover` 内嵌月份网格（3×4）。不引入新依赖——用 Popover + 自绘网格。范围同箭头约束。

## 三种月份下的 Detail 面板行为

### 过去月（只读模式）

| 区域 | 行为 |
|------|------|
| Summary Cards | 正常渲染终值（该月最终分配+最终消耗） |
| 消耗进度 | 定格终值，灰色调 |
| 子节点分配 | 表格展示，隐藏"编辑"按钮 |
| 项目预算 | 列表展示，隐藏"创建项目"按钮 |
| 成员额度 | 表格展示，隐藏"编辑"按钮 |

**视觉暗示**：整个 detail 区域覆盖一层极淡遮罩 `bg-muted/5`，或将所有 ActionButton 统一 `hidden`。推荐后者——简单且无视觉噪声。

### 当前月（仅上调模式）

| 区域 | 行为 |
|------|------|
| Summary Cards | 实时数据（正常刷新） |
| 消耗进度 | 实时进度（正常刷新） |
| 编辑部门预算 | 可编辑；输入框 `min={currentBudget}`，下调时 input 边框变红 + 底部提示 |
| 编辑成员额度 | 可编辑；个人额度输入框 `min={currentPersonalBudget}` |
| 项目 / Key | 正常创建编辑（已有行为不变） |

### 下月（自由编辑模式 — 含下调）

| 区域 | 行为 |
|------|------|
| Summary Cards | 第四张"本月消耗"替换为"预计消耗 —"（灰色破折号） |
| 消耗进度 | 进度条灰化 + 居中文字 "下月尚未开始" |
| 编辑部门预算 | 完全自由编辑，可上调也可下调 |
| 编辑成员额度 | 完全自由编辑 |
| 项目 | **仅可编辑已有项目的预算数字**。不可新建/删除项目（项目依赖主表 FK，需先在当月创建） |

**下调时触发 Reallocation Advisor（核心新交互，下一节详述）。**

## Reallocation Advisor — 下调分配引导

### 触发时机

在下月 period 下，管理员修改部门总预算时，如果新预算 < 已有分配总额，则弹出 Reallocation Advisor Dialog。

### Dialog 结构

```
┌── Reallocation Advisor ──────────────────────────────────────────────┐
│                                                                       │
│  ⚠  预算缩减需要重新分配                                             │
│                                                                       │
│  部门总预算 ¥100 → ¥60   │   缺口: ¥20                              │
│                                                                       │
│  ─── 建议方案 ───────────────────────────────────────────────────    │
│                                                                       │
│  策略说明：优先消耗预留池，剩余按原比例等额分摊至各子项              │
│                                                                       │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │  项目         原值     缩减     建议值     手动调整            │  │
│  │  ─────────────────────────────────────────────────────────────  │  │
│  │  ▸ 预留池     ¥10     -¥10      ¥0       [    0   ]          │  │
│  │  ▸ 子部门合计  ¥20     -¥3      ¥17      [   17   ]          │  │
│  │  ▸ 项目合计   ¥30     -¥4      ¥26      [   26   ]          │  │
│  │  ▸ 成员额度   ¥20     -¥3      ¥17      [   17   ]          │  │
│  │  ─────────────────────────────────────────────────────────────  │  │
│  │  合计         ¥80              ¥60       ¥60  ✓               │  │
│  └────────────────────────────────────────────────────────────────┘  │
│                                                                       │
│  💡 预留池优先释放 ¥10，剩余 ¥10 按原始比例分摊                      │
│                                                                       │
│  ┌─────────────────────────────────────────────────────────────────┐ │
│  │                                                                   │ │
│  │  [取消]          [我手动分配]          [应用建议方案]             │ │
│  │                                                                   │ │
│  └─────────────────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────────────┘
```

### 视觉规格

| 元素 | 规格 |
|------|------|
| Dialog 宽度 | `sm:max-w-xl` (560px) |
| 标题区 | 黄色 alert icon + "预算缩减需要重新分配" |
| 缩减摘要行 | `text-sm`，旧值灰色，新值黑色加粗，缺口红色 |
| 表格 | 轻量表格，无外框，行间 `divide-y` |
| "原值"列 | `text-muted-foreground tabular-nums` |
| "缩减"列 | `text-red-500 tabular-nums`，带减号 |
| "建议值"列 | `font-medium tabular-nums` |
| "手动调整"列 | 数字 Input (h-7 w-20)，初始填充建议值 |
| 合计行 | `font-semibold`，右侧展示实时合计 |
| 合计校验 | 合计 ≤ 新预算时绿色 ✓，超出时红色 ✗ + 错误提示 |
| Hint 文字 | `text-xs text-muted-foreground` + 💡 icon |
| 按钮区 | 三按钮：取消(ghost) / 我手动分配(outline) / 应用建议方案(default) |

### 三个按钮语义

| 按钮 | 行为 |
|------|------|
| **应用建议方案** | 以建议值（或用户手动调整后的值）写入下月分配，关闭 dialog |
| **我手动分配** | 只修改部门总预算为新值，不自动调子项。关闭 dialog 后用户回到详情面板手动改每个子项 |
| **取消** | 放弃本次修改，部门预算不变 |

### 手动调整列的实时校验

- 每个 Input onChange 时实时计算合计。
- 合计 > 新预算：Input 下方出现红色提示 "合计超出新预算 ¥X"，"应用建议方案"按钮 disabled。
- 任何单项输入 < 0：该 Input 边框变红。
- 所有项 ≥ 0 且合计 ≤ 新预算：绿色对勾 ✓。

### "我手动分配" 后的体验

用户回到正常的下月编辑模式，此时：
- 部门总预算已改为新值。
- 子项分配仍是旧值（继承值），必然超出新预算。
- 系统**不阻塞**：子项合计暂时超出部门预算是允许的预配态（尚未生效）。
- 在 Summary Cards 的"已分配"卡上显示红色 warning："已分配 ¥80 > 总预算 ¥60，请调整后保存"。
- 当月份生效前（下月1日零点）如果仍超出，系统发通知提醒管理员。

## "继承本月配置" 按钮

### 触发条件

切换到下月 period，且下月尚无分配记录。

### 交互

```
┌──────────────────────────────────────────────────────────┐
│  Period Bar                                               │
│   ◀  2026年9月  [预配中]🟡  ▶                            │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  ┌──── Empty State ────────────────────────────────┐    │
│  │                                                  │    │
│  │  📋  下月尚未配置预算                           │    │
│  │                                                  │    │
│  │  可从本月配置继承，或从零开始设置。              │    │
│  │                                                  │    │
│  │  [继承本月配置]  (primary)                       │    │
│  │  [从零开始]     (ghost, text-xs)                 │    │
│  │                                                  │    │
│  └──────────────────────────────────────────────────┘    │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

**继承本月配置**：调用 `POST /api/budget/periods/copy`，复制 budget / reservedPool / personalBudget / 项目 budget 到下月 period。consumed 全 0。成功后刷新页面展示下月分配。

**从零开始**：关闭 empty state，展示空的编辑面板（部门 budget=0，管理员从头设置）。

### 已有记录 & 再次继承

如果下月已有记录（管理员之前配过），Period Bar 右区不显示按钮。但管理员可通过"编辑部门总预算"正常修改。

### 当前月（活跃态）

```
┌────────────────────────────────────────────────────────┐

```

- Progress 颜色：默认 `bg-primary`。
- ≥70%: `bg-amber-500`。≥90%: `bg-red-500`。

### 过去月（定格态）

```
┌────────────────────────────────────────────────────────┐
│  当月消耗（终值）                      ¥78 / ¥100      │
│  ██████████████████████████░░░░  78%                   │

└────────────────────────────────────────────────────────┘
```

- 同样的颜色规则，但标题改为"当月消耗（终值）"。
- 副文字改为"使用率 X%"（不再说"剩余"因为已过去）。

### 下月（未开始态）

```
┌────────────────────────────────────────────────────────┐
│  预计消耗                                    —         │
│  ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░                    │
│  下月尚未开始，当前无消耗数据                          │
└────────────────────────────────────────────────────────┘
```

- Progress 条灰化: `bg-muted` 全灰，无填充。
- 右上角金额显示 "—"。
- 副文字: `text-xs text-muted-foreground`。

## 用户场景走查

### 场景 1: 财务总监月底预配下月

1. 进入预算管理页 → 看到当月视图，Period Bar 显示 "2026年8月 [本月]"
2. 点击 "预配下月 →" 按钮
3. 页面切到 2026年9月，显示 PeriodEmptyState
4. 点击 "继承本月配置"
5. 系统复制本月分配 → 页面刷新展示下月配置（consumed 全 0）
6. 总监编辑根部门预算 ¥100 → ¥80
7. 新预算 < 已分配 ¥80 → 弹出 Reallocation Advisor
8. 看到建议：预留池 ¥10→¥0，子部门/项目/成员 等比缩减
9. 手动把子部门 A 从建议的 ¥14 改为 ¥10（它上月用量少）
10. 调整项目预算从建议的 ¥22 改为 ¥26（核心项目多保留）
11. 合计 = ¥0 + ¥10 + ¥26 + ¥14(成员) = ¥50 ≤ ¥80 ✓
12. 点击 "应用建议方案" → 保存成功 → toast "下月预算分配已更新"
13. 回到下月详情面板确认分配无误

### 场景 2: TL 月中追加预算

1. 当月视图 → 选择自己的部门
2. 点击"编辑"部门预算 → 输入更大的值 → 保存
3. 成功，toast "预算已更新"
4. 尝试调低 → 输入框变红，提示 "本月预算仅支持上调"

### 场景 3: 新员工回顾上月

1. 在 Period Bar 点击 ◀ 切到上月
2. Badge 变为 "已结束"（灰色）
3. 所有编辑按钮消失
4. 查看各部门上月的分配和消耗情况
5. 了解完毕后点击 ▶ 回到本月
