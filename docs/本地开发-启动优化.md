# 本地开发指南

> 启动命令、就绪层级、日常使用决策树

---

## 一、就绪层级

| 层级 | 含义 | 由谁保证 | 验证方式 |
|------|------|----------|----------|
| **L0** | Backend + Frontend 进程可响应 | `pnpm start` / `pnpm start:lite` | `GET /healthz` |
| **L1** | Demo 数据 + Platform Key 已 sync | `pnpm reset` | `GET /api/dev/readiness` |
| **L2** | Gateway + 模拟消耗全通路 | `pnpm verify gate` | gate 脚本自验 |

---

## 二、命令速查

| 命令 | 用途 | 就绪目标 | 使用频率 |
|------|------|----------|----------|
| `pnpm reset` | 清库重建、种子数据 | L1 | 首次 clone / 改 seed / 清库 |
| `pnpm start` | 全量启动（backend + frontend + mock） | L0 | 测 Gateway / 模拟消耗 |
| `pnpm start:lite` | 轻量启动（仅 postgres + backend + frontend） | L0 | **日常推荐**（改 UI / API） |
| `pnpm infra` | 管理 Docker 基础设施 | 容器 up | 修 infra 配置 |
| `pnpm verify` | CI 检查（lint + test + build） | - | 提 PR 前 |
| `pnpm verify gate` | 全链路网关冒烟 | L2 | 通路验收 |

---

## 三、reset 详解

```bash
pnpm reset [local|saas] [--empty|--minimal|--full]
```

| 参数 | 默认 | 说明 |
|------|------|------|
| `local` | ✅ | 单公司模式 |
| `saas` | | 多租户平台 + demo 公司（强制 full seed） |
| `--empty` | | 空库，仅 admin 可登录 |
| `--minimal` | | 最小 seed |
| `--full` | ✅ | 完整 demo 数据 |

**reset 阶段链**：

1. `docker compose down -v` — 清卷
2. `postgres up --wait` — PG 就绪
3. `bootstrap-local-after-reset.sh` — 初始化 NewAPI + 生成 admin token → `.env.development`
4. `redis FLUSHALL` — 清缓存
5. `dev-bootstrap`（Go）— seed 数据 + Platform Key sync
6. `setup-dev-mock-channel.sh` — 配置测试模型通道

reset 完成后执行 `pnpm start` 或 `pnpm start:lite` 启动应用。

---

## 四、start vs start:lite

| 维度 | `pnpm start` | `pnpm start:lite` |
|------|-------------|-------------------|
| 基础设施 | `ensure-infra`（Postgres + Redis + NewAPI） | 仅 Postgres |
| 进程 | backend + frontend + dev-mock-llm | backend + frontend |
| 适用 | 需要 Gateway / 消耗测试 | 纯 UI / API 开发 |

两者都不做 seed、不 mint token、不 sync key。需要 L1 就绪必须先 `pnpm reset`。

---

## 五、infra 子命令

```bash
pnpm infra              # 全量 start-infra（Postgres + Redis + NewAPI）
pnpm infra postgres     # 仅 Postgres
pnpm infra redis        # 仅 Redis
pnpm infra attach       # docker compose up（前台，看日志）
```

## 六、决策树

```
刚 clone / 改了 seed / 要清库？
  → pnpm reset → pnpm start:lite

只改前端或 API？
  → pnpm start:lite

要测 Gateway / 模拟消耗？
  → 确保做过 reset → pnpm start

ensure-infra 报 no image？
  → pnpm reset（或 pnpm infra 重建）

readiness 503 但不想清库？
  → pnpm -F @tokenjoy/backend dev-bootstrap

验收全链路？
  → pnpm verify gate

提 PR？
  → pnpm verify
```

## 七、脚本结构

```
scripts/
  dev.sh                 # 入口分发器
  verify.sh              # CI / gate / integration 分发
  lib/common.sh          # 共享变量（ROOT, COMPOSE, NEWAPI_SCRIPTS）
  dev/
    start.sh             # full 启动
    start-lite.sh        # 轻量启动
    reset.sh             # 清库重建
    infra.sh             # 基础设施管理
    frontend-wait.sh     # 前端等待 backend 就绪后启动
    test.sh              # 测试
```

Docker Compose 文件位于 `apps/newapi/docker-compose.yml`，infra 脚本位于 `apps/newapi/scripts/`。

---

## 八、环境变量

reset 会自动写入 `apps/backend/.env.development`：

| 变量 | 说明 |
|------|------|
| `SUPPORT_SAAS` | `true`=多租户模式，`false`=单公司模式 |
| `NEW_API_ADMIN_TOKEN` | reset 时自动生成 |

`SEED` 环境变量（`empty`/`minimal`/`full`）通过命令行传入 `dev-bootstrap`，不持久化。
